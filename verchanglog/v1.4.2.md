# itdb-new v1.4.2 版本更新日志

**提交数量**: 2 次提交

## 📋 版本概述

本版本修复审计日志页面在 `ITDB_HISTORY_LIMIT=1000` 时仍只显示 500 条的问题：移除审计日志接口的固定返回上限与 2000 条硬限制，页面改为返回全部保留记录；`ITDB_HISTORY_LIMIT` 回归“仅控制历史表保留条数”的单一职责。同时移除清空接口对 ID 数量的 2000 条截断，并同步 Swagger 与项目文档。

---

## ✨ 新增特性

- 本版本无新增功能

---

## 🐛 Bug 修复

- **审计日志固定显示 500 条**：前端此前固定请求 `/api/history?limit=500`，后端默认值也固定为 500 且最大 2000，导致配置 `ITDB_HISTORY_LIMIT=1000` 后页面仍只显示 500 条；现改为默认返回历史表内全部保留记录
- **清空审计日志被截断**：清空接口此前最多处理 2000 个 ID，数据量超过 2000 时会剩余部分记录；现按前端提交的完整 ID 清单处理
- **前端每页 18 条的展示逻辑保持不变**：本次只调整数据加载总量与“共 xx 条”的统计来源，默认分页大小和分页器选项不变

## 🔄 API 变更

- `GET /api/history`：
  - 未传 `limit` 时返回历史表内全部保留记录，不再默认 500 条
  - `limit` 可选，不设最大 2000 限制；传 `-1` 等同于不限制
  - 响应中的 `limit` 为实际生效值，`-1` 表示不限制
- `POST /api/history/clear`：
  - 请求结构不变，取消服务端对 ID 数量的 2000 条截断
- `ITDB_HISTORY_LIMIT`：
  - 仅控制 `history` 表保留条数，不再作为接口默认返回条数
- 接口路径、鉴权方式与响应字段结构保持不变

## 🔄 升级说明

- 直接替换二进制或更新镜像即可，无迁移脚本，无需手工执行 SQL
- 升级后审计日志页面会展示历史表内全部保留记录，实际上限仍由 `ITDB_HISTORY_LIMIT` 控制
- 如需限制单次返回条数，可显式请求 `/api/history?limit=N`；该参数不再有 2000 条上限
